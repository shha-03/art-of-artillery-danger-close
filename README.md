# Art of Artillery: Danger Close

불변식을 작성해 공격 영역을 정하는 2D 포격 퍼즐입니다. 포대장은 고정된 프로그램을 관찰하고, 아군을 피하면서 여러 적을 한 번의 일제사로 제거할 수 있는 조건을 찾습니다. 기존 5개 작전에 신규 알고리즘 15개를 더해, 5개 챕터에서 총 20개 작전을 진행합니다.

## 언어 / Language

화면의 한국어 / English 스위치로 언어를 전환할 수 있습니다. 선택한 언어는 브라우저에 저장됩니다. 전투 도중 전환해도 현재 작전, 입력한 조건, 포격 결과와 남은 명령 등 진행 상태는 유지됩니다.

## 부대 기호

전장과 범례는 NATO APP-6의 지상부대 식별 프레임을 사용합니다. 아군은 파란 직사각형(`#80E0FF`), 적군은 빨간 마름모(`#FF8080`)이며, 현재 위치를 나타내는 검은 실선 테두리를 사용합니다. 내부 병과 기호는 보병의 교차선, 기갑의 타원, 포병의 검은 점입니다. 지도에는 병과별 획득·손실 점수가 함께 표시되고, 좌표 버튼의 텍스트 설명과 전력 명세에서도 확인할 수 있습니다. 제대 규모는 지정하지 않습니다.

| 병과 | 내부 기호 | 적 파괴 | 아군 피해 |
| --- | --- | --- | --- |
| 보병 | 교차선 X | +2 | −2 |
| 기갑 | 타원 | +4 | −4 |
| 포병 | 검은 점 | +6 | −6 |

적의 병과는 **단순한 범위 조건에서 아군을 분리해야 하는 정도**로 결정합니다. 각 적에 도달하는 허용 초기 입력을 모아 실행 경로의 x·y 범위를 구하고, 그 범위가 반복문 본문을 실행해도 유지되도록 확장합니다. 이 거친 조건의 종료 영역에 함께 들어오는 아군이 0기면 보병(2점), 1기면 기갑(4점), 2기 이상이면 포병(6점)입니다. 합·차·짝홀·비선형 관계 등을 보강해 섞인 아군을 배제해야 하는 표적에 높은 가치를 부여합니다. 전력 명세에는 해당 아군의 수와 좌표를 표시합니다.

같은 분리 요구에는 같은 점수를 부여하므로 적 병과가 중복될 수 있고, 작전별 적의 총점도 달라집니다. 아군은 기존 보병·기갑·포병 각 한 기와 손실 점수를 유지합니다. 단발의 좌표순이나 적과 아군 사이의 거리로 적의 가치를 정하지 않습니다. 일제사는 계속 명령 한 번으로 모든 후보를 타격합니다.

근거: [NATO APP-06(E) Version 1](https://coi.nato.int/EWCOI/EW%20COI%20Shared%20Documents/WGs/NEWWG/EW%20Info%20Exchange%20Requirements%20Panel%20%28IERP%29/01_Governing%20Documents/Publications/APP-06%20NATO%20Symbology/APP-06%20EDE%20V1%20E.pdf), §1.2.1 및 Tables 1-1·1-2(프레임·상태), Table 1-15(색상), §3.3.1 및 Table 3-1(일반 부대 프레임), Table 3-2의 Armour·Infantry·Field artillery(병과 기호). 게임의 포병은 야포(Field artillery) 기호로 표시합니다.

## 게임 방법

1. 전장의 적, 아군, 중립 칸과 고정된 초기 조건 `P`·반복 조건·반복문 본문을 확인합니다. `P`가 허용하는 각 입력으로 같은 반복문을 독립적으로 실행합니다.
2. 변수 `x`, `y`에 대한 불변식 `I`를 작성합니다. 비교 연산과 `&&`, `||`, 괄호를 사용해 영역을 표현할 수 있습니다.
3. 전장 배치를 보고 원하는 종료 상태 조건인 `ensures`, 즉 목표 `Q`를 작성합니다.
4. 초기 성립, 반복 보존, 목표 보장 결과와 반례를 확인하며 조건을 수정합니다.
5. 단발 또는 일제사 명령을 내려 적을 제거합니다. 라운드마다 명령은 6회입니다.

공격 후보는 다음 조건을 모두 만족하는 전장 좌표입니다.

```text
S = I && !guard
```

허용된 모든 초기 상태에서 `I`가 참이고, `I && guard`인 모든 검증 상태에 본문을 한 번 실행해도 `I`가 유지되어야 발사할 수 있습니다. 초기 입력 중 하나라도 빠뜨리거나 보존 검사가 실패하면 불발입니다. `I && !guard`가 `Q`를 보장하는지는 별도로 표시하며, 목표 조건을 바꾼다고 공격 후보 자체가 바뀌지는 않습니다.

초기 성립의 의미는 `P => I`입니다. 좌표 표준화(화면의 작전 08)를 제외한 19개 작전은 명시된 세 좌표만 초기 입력으로 허용합니다. 좌표 표준화의 `P = true`는 수학적으로 모든 정수 쌍을 허용하므로, 불변식도 모든 정수 쌍에서 참이어야 초기 성립을 만족합니다. `true`가 가장 단순한 해법이며, 입력을 일부 제외하는 조건은 해법이 될 수 없습니다. 현재 엔진이 실제로 검사하는 범위는 아래에 명시한 `[-32,32]²`입니다.

초기 성립 실패는 조건에서 빠진 초기 상태를, 반복 보존 실패는 반복 전후의 상태를, 목표 보장 실패는 목표를 만족하지 않는 종료 후보를 보여줍니다. 보존·목표 반례는 실제 실행 경로에 없는 상태일 수도 있습니다. 이 반례를 이용해 불변식이나 목표를 수정하세요.

## 포격과 점수

- 단발은 공격 후보 중 한 칸을 포격합니다. 일제사는 공격 후보 전체를 포격합니다.
- 두 방식 모두 명령 1회만 사용합니다. 일제사의 발사 수가 많아져도 명령 비용은 늘어나지 않습니다.
- 표적 우선순위는 중립 칸 → 아군 → 적입니다. 같은 종류에서는 고정된 좌표순을 사용합니다.
- 포격을 완료한 칸은 이후 후보에서 제외됩니다. 파괴된 적·아군의 칸도 중립 칸으로 다시 공격하지 않습니다.
- 빈칸은 중립 칸입니다. 중립 칸 포격 자체에는 처치 점수가 없습니다.

```text
점수 = 파괴한 적의 병과 점수 합계 - 피해를 입힌 아군의 병과 점수 합계 + 남은 명령 횟수
```

세 적의 가치 합계를 V라고 하면, 세 적만 정확히 겨냥한 단발 3회는 `V + 3점`, 일제사 1회는 `V + 5점`입니다. 아군 피해는 해당 병과의 2·4·6점을 차감하며 처치 수는 점수와 별도로 집계합니다. 중립 칸은 처치 점수에 영향을 주지 않으며, 일제사에서 추가 명령 비용도 만들지 않습니다. 포격한 칸에는 점수를 중복 적용하지 않습니다.

새 최고 점수는 `danger-close-best-precision-v1`에 기록합니다. 이전 병과 배점 기록(`danger-close-best-branches-v1`)과 병과 도입 이전 기록(`danger-close-best-math-v2`)은 각각 구분해 보존하며 새 점수와 비교하거나 덮어쓰지 않습니다. 기존 완료 기록은 캠페인 진행 표시에 계속 반영합니다.

### 배점에 사용하는 정밀도 모델

배점 계산은 같은 유한 검증 세계에서 다음 절차를 사용합니다.

1. 초기 성립과 유지가 검증된 넓은 시작 불변식을 기준 B로 삼습니다. 무제약 입력의 좌표 표준화는 B = true를 사용합니다.
2. 허용 초기 입력을 실제 종료 좌표별로 묶습니다. 조건식 입력은 대표 경로만 사용하지 않고 검증 범위의 모든 허용 입력을 사용합니다.
3. 각 그룹의 실행 경로를 포함하는 x·y 직사각형 범위를 만듭니다. B와 범위를 함께 만족하는 모든 반복 상태의 후속 상태까지 범위를 넓히며, 더 이상 넓어지지 않을 때까지 반복합니다.
4. 완성된 조건 `B ∧ 범위 ∧ ¬guard`가 포함하는 아군을 셉니다. 반복 중인 아군 좌표는 포격 후보가 아니므로 세지 않습니다. 그 수를 0·1·2기 이상 세 등급으로 나눕니다.

각 그룹의 조건을 OR로 연결하면 전체 초기 성립과 유지가 성립하는 거친 불변식이 됩니다. 따라서 표시된 아군은 실제로 유효한 거친 불변식에서 발생하는 오폭 후보입니다. 예시 정밀 불변식에서는 이 아군들이 모두 제외됩니다. 모든 유효한 불변식은 실제 적 종료점을 함께 포함하므로, 이 값은 위 범위 모델에서 잃어버린 관계를 보완하는 요구를 나타내는 게임 배점입니다. 가능한 모든 수식의 최단 길이나 절대적인 증명 난도를 계산하는 것은 아닙니다.

예를 들어 피보나치 신호의 `(3,5)`는 아군 2기를 함께 포함해 6점이고, 그다음 단발 표적인 `(3,6)`은 아군 1기를 포함해 4점입니다. 홀수 누산 제곱의 `(0,0)`은 아군이 섞이지 않아 2점이며 `(0,1)`, `(0,4)`는 각각 6점입니다. 좌표 표준화는 종료 조건 자체가 아군을 모두 배제하므로 세 적 모두 2점입니다.

챕터마다 네 작전이 있으며, 범위와 합·차에서 시작해 분기, 누적 계산, 비선형 관계, 종합 검증으로 진행합니다. 아래 번호는 화면에 표시되는 진행 순서입니다. 저장 기록에 사용하는 내부 레벨 ID와는 구분합니다.

| 15 | 4. 비선형 관계 | 이진 자리값 누적 — 남은 자리에 1을 붙여 세 자리 이진수 완성 | `y+1`의 배가 관계, 약수 조건, 처리 자리 수의 경계 |
| 16 | 4. 비선형 관계 | 회전 정규화 — 축 위 벡터를 90도씩 회전해 양의 x축에 정렬 | 회전에 따른 제곱합 `x*x + y*y` 보존 |
| 17 | 5. 종합 검증 | 이진 경계 탐색 — 입력 구간에서 3 이상인 첫 정수 탐색 | 정답을 포함하는 탐색 구간과 입력별 경우의 논리합 |
| 18 | 5. 종합 검증 | 최대공약수 감산 — 큰 수에서 작은 수를 반복 차감 | 공통약수 보존과 양수·상한 조건의 결합 |
| 19 | 5. 종합 검증 | 피보나치 신호 — 배율이 다른 피보나치 쌍을 순차 생성 | `x*x + x*y - y*y`의 부호 반전과 절댓값 보존 |
| 20 | 5. 종합 검증 | Pell 정수쌍 — √2를 근사하는 정수쌍 생성 | `x*x - 2*y*y`의 부호 반전과 좌표 경계 |

각 좌표는 `(x, y)`입니다. 모든 작전의 적 세 기는 허용 입력의 실제 종료 좌표 세 곳에 정확히 배치됩니다. 좌표 표준화(작전 08)에서 표시하는 `(6,3) → (0,0)`, `(-5,2) → (1,0)`, `(2,-3) → (2,0)`은 대표 경로입니다. 실제 초기 조건은 이 세 입력으로 제한되지 않습니다.

정수 나눗셈의 종료 시 `y`는 몫, `x`는 나머지입니다. 제곱근 탐색의 종료 시 `y`는 입력의 제곱근을 내림한 정수이고, `x`는 입력에서 `y*y`를 뺀 나머지입니다. 이진 자리값 누적은 남은 자리에 모두 1을 붙이는 제한된 호너 방식으로 `001`, `011`, `111`을 계산합니다. 좌표 표준화는 음수 입력도 0, 1, 2 중 하나로 바꾸는 유클리드 나머지를 계산하며, 초기 조건이 무제약일 때 종료 조건 자체로 결과 범위를 정할 수 있음을 보여줍니다.

명시된 초기 입력 목록은 `initialStates`, 초기 사전조건 식은 `initialCondition`에 정의하며 둘을 동시에 사용하지 않습니다. 조건식 방식의 `traceInputs`는 화면에 그릴 대표 실행 경로만 선택하고, 초기 성립 검사 범위를 좁히지 않습니다. 화면의 실행 가능한 반복문은 `code`, 한 단계 전이는 `step`에 정의됩니다. 초기 입력을 반복문 안에서 다시 대입하지 않습니다.

각 작전에는 단계별 힌트 세 개가 있습니다. 마지막 힌트는 예시 불변식입니다. 레벨 데이터의 `solution`과 `goalSolution`에는 검증 가능한 예시를 제공합니다. 예시 불변식의 종료 후보와 예시 목표가 허용하는 상태는 모두 실제 종료 좌표 세 곳과 일치합니다. 좌표 표준화를 제외한 19개 작전의 시작 불변식은 초기 성립과 보존을 통과하지만 아군을 포함하는 더 넓은 종료 영역을 허용하므로, 목표 보장에는 실패합니다. 좌표 표준화(작전 08)의 시작 불변식 `x >= 0 && y >= 0`은 허용된 음수 입력을 제외하므로 초기 성립부터 실패합니다.

## 검증 범위와 설계

검증 엔진은 `x`, `y`가 각각 -32부터 32까지인 모든 정수 상태를 검사합니다. 화면의 9×9 전장보다 넓은 유한 상태 공간에 대한 정확한 열거 검사이며, 무한한 정수 전체에 대한 정리 증명은 아닙니다. 반복 보존 검사에서 전이 결과를 경계로 잘라내거나 경계 밖으로 나가는 전이를 무시하지 않습니다. 결과가 검증 범위를 벗어나면 보존 실패로 처리합니다.

조건식 방식의 초기 검사는 이 4,225개 상태 중 `P`가 참인 상태를 모두 검사합니다. 따라서 좌표 표준화(작전 08)는 대표 경로가 세 개여도 초기 상태 4,225개를 검사합니다. 화면에서 검사 통과로 표시되는 것은 이 한정된 범위에 대한 결과이며, `P = true`라는 수학적 명세와 엔진의 유한 검사 범위를 구분해야 합니다.

각 초기 입력은 하나의 결정적인 실행 경로를 만듭니다. 허용 입력의 실제 종료 좌표 집합은 적 세 기의 위치와 일치합니다. 불변식은 실제로 도달하지 않는 상태도 포함할 수 있으므로, 포격 영역인 `I && !guard`는 이 실제 결과보다 넓어질 수 있습니다. 입력별 실행 경로와 불변식이 허용하는 종료 후보는 구분해야 합니다. 종료 여부 자체를 증명하는 게임은 아닙니다.

레벨·캠페인 테스트는 고정된 초기 입력을 사용하는 작전의 표시된 JavaScript 반복문을 각 입력으로 독립 실행하고, 그 결과를 수학적 계산 결과 및 `step` 기반 실행 경로의 끝점과 비교합니다. 좌표 표준화는 음수와 검사 범위의 경계값을 포함해 표시 코드의 실행 결과를 확인하며, 4,225개 상태 각각에서 `step` 실행의 종료·범위 유지·유클리드 나머지를 검사합니다. 실제 종료 좌표·적 배치·예시 목표·예시 불변식의 종료 집합 일치와 대표 경로가 초기 검사 범위를 제한하지 않는지도 검사합니다.

플레이어가 입력한 조건식은 전용 파서로 해석하며 `eval`이나 `Function`으로 실행하지 않습니다. 고정된 프로그램 본문에 있는 나눗셈이나 `Math.floor`는 플레이어 조건식의 지원 문법에 포함되지 않습니다. 조건식에서는 정수 산술의 정확한 표현 범위를 벗어나는 연산과 0을 제수로 하는 나머지 연산을 오류로 처리합니다.

플레이어의 수정을 이끄는 핵심은 세 종류의 반례, 전장 위의 공격 영역, 단발과 일제사의 선택입니다. 프로그램은 고정하고 불변식과 목표만 편집하게 해, 조건을 수정하는 행동이 공격 결과에 직접 연결되도록 설계했습니다.
