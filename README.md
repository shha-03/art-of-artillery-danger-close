# Art of Artillery: Danger Close

불변식을 작성해 공격 영역을 정하는 2D 포격 퍼즐입니다. 포대장은 고정된 프로그램을 관찰하고, 아군을 피하면서 여러 적을 한 번의 일제사로 제거할 수 있는 조건을 찾습니다.

## 언어 / Language

화면의 한국어 / English 스위치로 언어를 전환할 수 있습니다. 선택한 언어는 브라우저에 저장됩니다. 전투 도중 전환해도 현재 작전, 입력한 조건, 포격 결과와 남은 명령 등 진행 상태는 유지됩니다.

Use the 한국어 / English switch to change language. Your preference is saved in this browser. Switching during combat preserves the current mission, entered conditions, firing results, and remaining commands.

## 실행

Node.js 20 이상이 필요합니다. 프로젝트 디렉터리에서 다음 명령을 실행한 뒤, 터미널에 출력된 주소를 브라우저로 여세요. 기본 주소는 [로컬 게임](http://127.0.0.1:4173)입니다.

```sh
npm install
npm run build
npm start
```

검증 엔진과 언어 지원의 자동 테스트는 다음과 같이 실행합니다.

```sh
npm test
```

`npm run build`는 공식 `z3-solver` 패키지에서 브라우저용 JavaScript와 압축된 WebAssembly 파일을 `dist/vendor/`에 생성합니다. 게임 화면과 레벨 데이터는 `dist/`에 있습니다. 빌드 후 `dist/vendor/`를 포함한 `dist/` 전체를 배포해야 합니다.

브라우저 실행에는 HTTPS 또는 localhost와 다음 응답 헤더가 필요합니다. `npm start`의 서버는 이 헤더를 제공합니다. 다른 호스팅에서도 같은 설정을 적용하세요.

```text
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

브라우저는 WebAssembly, SharedArrayBuffer, DecompressionStream을 지원해야 합니다. 검증 시 Z3 런타임을 불러옵니다. 최초 엔진 초기화 제한은 45초이며, 각 검증 항목은 정의성 검사와 논리 질의를 합쳐 기본 2초까지 계산합니다. 이는 계산 시간 제한으로, 정수의 크기나 증명 범위를 제한하지 않습니다. 초기화 실패나 시간 초과는 명령을 차감하지 않는 오류로 표시합니다.

호스팅이 위 헤더를 제공하지 않으면 `bootstrap.js`가 게임 시작 전에 같은 출처의 `isolation-worker.js`를 등록합니다. 이 대안은 [coi-serviceworker의 접근법](https://github.com/gzuidhof/coi-serviceworker)을 따르며, 서비스 워커가 제어권을 얻은 뒤 탭 세션당 최대 한 번만 새로고침합니다. 이미 격리된 환경에서는 즉시 게임을 시작합니다. 등록 대기 제한은 8초이며, 등록·격리에 실패하면 게임을 표시하고 검증 시 기존 오류 안내를 사용합니다. 플레이가 시작된 뒤에는 서비스 워커 갱신으로 자동 새로고침하지 않습니다.

서비스 워커는 알려진 게임 문서와 같은 출처의 정적 자산에만 응답 헤더를 추가합니다. 인증 페이지·API·외부 요청·리디렉션·실패 응답에는 개입하지 않으며, 요청의 쿠키와 인증 정보도 변경하지 않습니다. 응답을 별도로 캐시하거나 저장하지 않습니다. 서비스 워커나 상위 프레임의 격리 권한을 브라우저가 제한하는 환경에서는 이 대안이 작동하지 않을 수 있으므로, 서버에서 헤더를 제공하는 구성이 우선입니다.

## 게임 방법

1. 전장의 적, 아군, 중립 칸과 고정된 초기값·반복 조건·반복문 본문을 확인합니다.
2. 변수 `x`, `y`에 대한 불변식 `I`를 작성합니다. 비교 연산과 `&&`, `||`, 괄호를 사용해 영역을 표현할 수 있습니다.
3. 전장 배치를 보고 원하는 종료 상태 조건인 `ensures`, 즉 목표 `Q`를 작성합니다.
4. 초기 성립, 반복 보존, 목표 보장 결과와 반례를 확인하며 조건을 수정합니다.
5. 단발 또는 일제사 명령을 내려 적을 제거합니다. 라운드마다 명령은 6회입니다.

공격 후보는 다음 조건을 모두 만족하는 전장 좌표입니다.

```text
S = I && !guard
```

초기값에서 `I`가 참이고, `I && guard`인 모든 정수 상태에 본문을 한 번 실행해도 `I`가 유지되어야 발사할 수 있습니다. 이 두 검사 중 하나라도 반례가 발견되면 불발이며 명령 1회를 소모합니다. `I && !guard`가 `Q`를 보장하는지는 별도로 표시합니다. 목표 보장에 반례가 있어도 초기·유지 검사가 통과하면 발사하며, 목표 조건을 바꾼다고 공격 후보 자체가 바뀌지는 않습니다.

검증이 `unknown`으로 끝나거나 시간 초과로 판정되지 않으면 발사를 중단하고 명령을 차감하지 않습니다. 문법·산술 오류, 또는 초기·유지 검사를 통과했지만 미포격 후보가 없는 경우도 명령을 차감하지 않습니다.

초기 성립 실패는 초기 상태를, 반복 보존 실패는 반복 전후의 상태를, 목표 보장 실패는 목표를 만족하지 않는 종료 후보를 보여줍니다. 이 반례를 이용해 불변식이나 목표를 수정하세요.

## 포격과 점수

- 단발은 공격 후보 중 한 칸을 포격합니다. 일제사는 공격 후보 전체를 포격합니다.
- 두 방식 모두 명령 1회만 사용합니다. 일제사의 발사 수가 많아져도 명령 비용은 늘어나지 않습니다.
- 표적 우선순위는 중립 칸 → 아군 → 적입니다. 같은 종류에서는 고정된 좌표순을 사용합니다.
- 포격을 완료한 칸은 이후 후보에서 제외됩니다. 파괴된 적·아군의 칸도 중립 칸으로 다시 공격하지 않습니다.
- 빈칸은 중립 칸입니다. 중립 칸 포격 자체에는 처치 점수가 없습니다.

```text
점수 = 적 처치 수 - 아군 처치 수 + 남은 명령 횟수
```

단발로 적 한 기를 처치하면 처치 점수와 명령 비용이 상쇄됩니다. 일제사로 적 여러 기를 함께 제거하면 점수가 올라갑니다. 중립 칸은 일제사에서 추가 명령 비용을 만들지 않으므로, 아군을 제외하는 조건을 찾는 것이 중요합니다.

## 네 개의 작전

| 작전 | 반복문의 특징 | 찾을 관계 |
| --- | --- | --- |
| 01. 대각선 교두보 | `x`, `y`가 함께 1씩 증가 | 같은 값의 관계와 공격 영역의 상한 |
| 02. 협곡 호송대 | `x`만 증가 | 변하지 않는 `y`와 범위의 결합 |
| 03. 두 배의 고도 | `x`는 1, `y`는 2씩 증가 | `y = 2 * x`라는 선형 관계 |
| 04. 능선 너머 | `x = 2`에서 `y`의 증감 방향 변경 | 두 구간의 관계를 논리합으로 연결 |

각 작전에는 단계별 힌트 세 개가 있습니다. 마지막 힌트는 예시 불변식입니다. 레벨 데이터의 `solution`과 `goalSolution`에는 검증 가능한 예시를 제공합니다.

## Z3 검증과 전이 명세

검증 엔진은 Z3의 `Int` 정렬을 사용해 상한·하한이 없는 수학적 정수 위에서 조건을 검사합니다. 정수 연산은 임의 정밀도 의미를 가지며, 유한 범위를 열거하거나 기계 정수의 오버플로를 가정하지 않습니다.

초기 상태를 `(x0, y0)`, 한 번의 반복 실행을 `T`, 목표를 `Q`라고 하면 다음 세 종류의 반례를 Z3에 질의합니다.

| 검사 | 반례 조건 |
| --- | --- |
| 초기 성립 | `x == x0 && y == y0 && !I(x, y)` |
| 반복 보존 | `I(x, y) && guard(x, y) && !I(T(x, y))` |
| 목표 보장 | `I(x, y) && !guard(x, y) && !Q(x, y)` |

각 질의가 `sat`이면 반례가 존재하므로 해당 검사는 실패합니다. `unsat`이면 반례가 없으므로 통과합니다. `unknown`은 통과도 실패도 아니며, 발사를 보류합니다. 화면은 반례 모델의 좌표를 표시합니다. 반복 보존의 반례는 실제 실행에서 도달하지 않는 상태일 수도 있습니다.

레벨의 `transition`은 다음 `x`, `y`를 만드는 식을 선언합니다. 모든 식과 분기 조건은 동일한 이전 상태를 참조하며, 새 좌표는 동시에 결정됩니다. 예를 들어 `transition: { x: 'x + 1', y: 'y + 1' }`은 두 값을 각각 1씩 증가시킵니다. 분기는 `{ condition, then, else }`로 표현합니다. 작전 04의 분기 조건은 증가시키기 전의 `x`를 사용하므로 화면 코드의 `y` 갱신 후 `x` 증가와 같은 의미입니다.

9×9 전장은 검증 범위가 아니라 공격 후보를 표시하는 유한 지도입니다. 전체 정수 영역의 종료 후보 `I && !guard`를 전장 좌표에 투영한 뒤, 이미 포격한 칸을 제외해 실제 표적을 정합니다. 화면 밖의 반례도 검증 실패의 근거가 되며, 포격한 칸을 증명 조건에서 제거하지는 않습니다.

불변식은 실제로 도달하지 않는 상태도 포함할 수 있습니다. 따라서 고정된 결정적 프로그램의 실제 종료 좌표가 하나여도, 여러 종료 후보 좌표를 한 번에 공격할 수 있습니다. 이 검증은 프로그램이 종료한다는 사실을 증명하지 않습니다.

플레이어의 수정을 이끄는 핵심은 세 종류의 반례, 전장 위의 공격 영역, 단발과 일제사의 선택입니다. 프로그램은 고정하고 불변식과 목표만 편집하게 해, 조건을 좁히는 행동이 공격 결과에 직접 연결되도록 설계했습니다.

## 산술식의 의미

`%`는 JavaScript와 같은 부호 규칙의 정수 나머지입니다. 0이 아닌 결과의 부호는 피제수와 같으며, 예를 들어 `-5 % 3 == -2`, `5 % -3 == 2`입니다. 실제로 평가되는 경로에서 제수가 0이면 산술 오류로 처리합니다. `y != 0 && x % y == 0`처럼 왼쪽 조건으로 제수 0을 배제할 수 있습니다. `&&`, `||`는 왼쪽부터 단락 평가하므로, 실행되지 않는 분기의 나머지 연산은 평가하지 않습니다.
