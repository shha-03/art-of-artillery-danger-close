# Art of Artillery: Danger Close

불변식을 작성해 공격 영역을 정하는 2D 포격 퍼즐입니다. 포대장은 고정된 프로그램을 관찰하고, 아군을 피하면서 여러 적을 한 번의 일제사로 제거할 수 있는 조건을 찾습니다.

## 언어 / Language

화면의 한국어 / English 스위치로 언어를 전환할 수 있습니다. 선택한 언어는 브라우저에 저장됩니다. 전투 도중 전환해도 현재 작전, 입력한 조건, 포격 결과와 남은 명령 등 진행 상태는 유지됩니다.

Use the 한국어 / English switch to change language. Your preference is saved in this browser. Switching during combat preserves the current mission, entered conditions, firing results, and remaining commands.

## 실행

프로젝트 디렉터리에서 다음 명령을 실행한 뒤, 터미널에 출력된 주소를 브라우저로 여세요.

```sh
node server.mjs
```

검증 엔진, 언어 지원, 레벨의 수학적 의미를 검사하는 자동 테스트는 다음과 같이 실행합니다.

```sh
node --test engine.test.mjs i18n.test.mjs level-semantics.test.mjs
```

게임 화면과 레벨 데이터는 `dist/`에 있습니다. 별도의 빌드 없이 정적 웹 서버로 제공할 수 있습니다.

## 게임 방법

1. 전장의 적, 아군, 중립 칸과 고정된 초기 조건 `P`·반복 조건·반복문 본문을 확인합니다. `P`가 허용하는 각 입력으로 같은 반복문을 독립적으로 실행합니다.
2. 변수 `x`, `y`에 대한 불변식 `I`를 작성합니다. 비교 연산과 `&&`, `||`, 괄호를 사용해 영역을 표현할 수 있습니다.
3. 전장 배치를 보고 원하는 종료 상태 조건인 `ensures`, 즉 목표 `Q`를 작성합니다.
4. 초기 성립, 반복 보존, 목표 보장 결과와 반례를 확인하며 조건을 수정합니다.
5. 단발 또는 일제사 명령을 내려 적을 제거합니다. 라운드마다 명령은 6회입니다.

공격 후보는 다음 조건을 모두 만족하는 전장 좌표입니다.

```text
S = I && !guard
```

허용된 모든 초기 상태에서 `I`가 참이고, `I && guard`인 모든 검증 상태에 본문을 한 번 실행해도 `I`가 유지되어야 발사할 수 있습니다. 초기 입력 중 하나라도 빠뜨리거나 보존 검사가 실패하면 불발입니다. `I && !guard`가 `Q`를 보장하는지는 별도로 표시하며, 목표 조건을 바꾼다고 공격 후보 자체가 바뀌지는 않습니다.

초기 성립의 의미는 `P => I`입니다. 작전 01–04는 명시된 세 좌표만 초기 입력으로 허용합니다. 작전 05의 `P = true`는 수학적으로 모든 정수 쌍을 허용하므로, 불변식도 모든 정수 쌍에서 참이어야 초기 성립을 만족합니다. `true`가 가장 단순한 해법이며, 입력을 일부 제외하는 조건은 해법이 될 수 없습니다. 현재 엔진이 실제로 검사하는 범위는 아래에 명시한 `[-32,32]²`입니다.

초기 성립 실패는 조건에서 빠진 초기 상태를, 반복 보존 실패는 반복 전후의 상태를, 목표 보장 실패는 목표를 만족하지 않는 종료 후보를 보여줍니다. 보존·목표 반례는 실제 실행 경로에 없는 상태일 수도 있습니다. 이 반례를 이용해 불변식이나 목표를 수정하세요.

## 포격과 점수

- 단발은 공격 후보 중 한 칸을 포격합니다. 일제사는 공격 후보 전체를 포격합니다.
- 두 방식 모두 명령 1회만 사용합니다. 일제사의 발사 수가 많아져도 명령 비용은 늘어나지 않습니다.
- 표적 우선순위는 중립 칸 → 아군 → 적입니다. 같은 종류에서는 고정된 좌표순을 사용합니다.
- 포격을 완료한 칸은 이후 후보에서 제외됩니다. 파괴된 적·아군의 칸도 중립 칸으로 다시 공격하지 않습니다.
- 빈칸은 중립 칸입니다. 중립 칸 포격 자체에는 처치 점수가 없습니다.

```text
점수 = 적 처치 수 - 아군 처치 수 + 남은 명령 횟수
```

단발로 적 한 기를 처치하면 처치 점수와 명령 비용이 상쇄됩니다. 세 적만 정확히 겨냥하면 단발 3회로 6점, 일제사 1회로 8점을 얻습니다. 중립 칸은 일제사에서 추가 명령 비용을 만들지 않으므로, 아군을 제외하는 조건을 찾는 것이 중요합니다.

## 다섯 개의 작전

각 좌표는 `(x, y)`입니다. 각 작전의 적 세 기는 허용 입력의 실제 종료 좌표 세 곳에 정확히 배치됩니다. 작전 05에서 표시하는 세 입력은 전체 초기 입력 집합을 대신하는 대표 경로일 뿐입니다.

| 작전 | 계산 목적과 반복 동작 | 초기 입력 → 실제 종료 좌표 | 보존되는 관계 |
| --- | --- | --- | --- |
| 01. 덧셈 이송 | `x > 0` 동안 `x`를 1 줄이고 `y`를 1 늘려 합을 `y`로 이전 | `(2,2) → (0,4)`, `(4,2) → (0,6)`, `(6,2) → (0,8)` | `x + y`는 입력에 따라 4, 6, 8 |
| 02. 정수 나눗셈 | `x >= 3` 동안 `x`에서 3을 빼고 `y`를 1 늘려 나머지와 몫 계산 | `(5,0) → (2,1)`, `(6,0) → (0,2)`, `(8,0) → (2,2)` | `x + 3 * y`는 5, 6, 8 |
| 03. 삼각수 집결 | `x > 0` 동안 `y`에 현재 `x`를 더한 뒤 `x`를 1 감소 | `(1,0) → (0,1)`, `(2,0) → (0,3)`, `(3,0) → (0,6)` | `2 * y + x * (x + 1)`은 2, 6, 12 |
| 04. 제곱근 탐색 | `x >= 2 * y + 1` 동안 다음 홀수를 빼고 `y`를 1 증가 | `(2,0) → (1,1)`, `(5,0) → (1,2)`, `(8,0) → (4,2)` | `x + y * y`는 2, 5, 8 |
| 05. 좌표 표준화 | `x`가 음수이면 3 증가, 3 이상이면 3 감소하고 `y`는 독립적으로 0에 한 칸 접근 | 모든 정수 쌍 허용. 대표 경로: `(6,3) → (0,0)`, `(-5,2) → (1,0)`, `(2,-3) → (2,0)` | `I = true`; 종료 조건만으로 `0 <= x < 3` 및 `y == 0` 보장 |

나눗셈의 종료 시 `y`는 몫, `x`는 나머지입니다. 제곱근의 종료 시 `y`는 입력의 제곱근을 내림한 정수이고, `x`는 입력에서 `y * y`를 뺀 나머지입니다. 좌표 표준화의 종료 시 `x`는 음수 입력도 0, 1, 2 중 하나로 바꾸는 유클리드 나머지이며 `y`는 0입니다. 이 작전은 초기 조건이 무제약일 때 불변식을 좁힐 수 없고, 반복 종료 조건 자체가 결과 범위를 정할 수 있음을 보여줍니다.

명시된 초기 입력 목록은 `initialStates`, 초기 사전조건 식은 `initialCondition`에 정의하며 둘을 동시에 사용하지 않습니다. 조건식 방식의 `traceInputs`는 화면에 그릴 대표 실행 경로만 선택하고, 초기 성립 검사 범위를 좁히지 않습니다. 화면의 실행 가능한 반복문은 `code`, 한 단계 전이는 `step`에 정의됩니다. 초기 입력을 반복문 안에서 다시 대입하지 않습니다.

각 작전에는 단계별 힌트 세 개가 있습니다. 마지막 힌트는 예시 불변식입니다. 레벨 데이터의 `solution`과 `goalSolution`에는 검증 가능한 예시를 제공합니다. 예시 불변식의 종료 후보와 예시 목표가 허용하는 상태는 모두 실제 종료 좌표 세 곳과 일치합니다. 작전 01–04의 시작 불변식은 초기 성립과 보존을 통과하지만 아군을 포함하는 더 넓은 종료 영역을 허용하므로, 목표 보장에는 실패합니다. 작전 05의 시작 불변식 `x >= 0 && y >= 0`은 허용된 음수 입력을 제외하므로 초기 성립부터 실패합니다.

## 검증 범위와 설계

검증 엔진은 `x`, `y`가 각각 -32부터 32까지인 모든 정수 상태를 검사합니다. 화면의 9×9 전장보다 넓은 유한 상태 공간에 대한 정확한 열거 검사이며, 무한한 정수 전체에 대한 정리 증명은 아닙니다. 반복 보존 검사에서 전이 결과를 경계로 잘라내거나 경계 밖으로 나가는 전이를 무시하지 않습니다. 결과가 검증 범위를 벗어나면 보존 실패로 처리합니다.

조건식 방식의 초기 검사는 이 4,225개 상태 중 `P`가 참인 상태를 모두 검사합니다. 따라서 작전 05는 대표 경로가 세 개여도 초기 상태 4,225개를 검사합니다. 화면에서 검사 통과로 표시되는 것은 이 한정된 범위에 대한 결과이며, `P = true`라는 수학적 명세와 엔진의 유한 검사 범위를 구분해야 합니다.

각 초기 입력은 하나의 결정적인 실행 경로를 만듭니다. 허용 입력의 실제 종료 좌표 집합은 적 세 기의 위치와 일치합니다. 불변식은 실제로 도달하지 않는 상태도 포함할 수 있으므로, 포격 영역인 `I && !guard`는 이 실제 결과보다 넓어질 수 있습니다. 입력별 실행 경로와 불변식이 허용하는 종료 후보는 구분해야 합니다. 종료 여부 자체를 증명하는 게임은 아닙니다.

레벨 테스트는 작전 01–04의 표시된 JavaScript 반복문을 각 입력으로 독립 실행하고, 그 결과를 수학적 계산 결과 및 `step` 기반 실행 경로의 끝점과 비교합니다. 작전 05는 음수와 검사 범위의 경계값을 포함해 표시 코드의 실행 결과를 확인하며, 4,225개 상태 각각에서 `step` 실행의 종료·범위 유지·유클리드 나머지를 검사합니다. 실제 종료 좌표·적 배치·예시 목표·예시 불변식의 종료 집합 일치와 대표 경로가 초기 검사 범위를 제한하지 않는지도 검사합니다.

플레이어의 수정을 이끄는 핵심은 세 종류의 반례, 전장 위의 공격 영역, 단발과 일제사의 선택입니다. 프로그램은 고정하고 불변식과 목표만 편집하게 해, 조건을 좁히는 행동이 공격 결과에 직접 연결되도록 설계했습니다.
